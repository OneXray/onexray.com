При создании выберите **обычную конфигурацию** или **продвинутый JSON**. Лимит в три профиля общий, редакторы и типы импорта независимы. Продвинутый JSON использует общие инструменты импорта, обмена, сохранения и удаления, а также ссылку на документацию. DNS, sniffing и дополнительные inbounds описаны в [контракте шаблона]({{< relref "/docs/configuration/advanced-routing" >}}). Дальнейшие инструкции формы правил относятся только к обычному режиму.

Откройте Подключение → режим трафика → собственный маршрут. Создайте профиль или импортируйте файл; реальные серверы выбираются на Подключении.

## Редактирование

Уникальное имя, 1–3 входных узла для автоматического/группового выбора, до трёх профилей. Фиксированный одиночный сервер остаётся одним входом.

Редактирование правила меняет черновик; сохраните весь профиль закреплённой нижней кнопкой. Удаление находится в строке правила, переключателей enable/disable нет. Эффективное изменение активного маршрута требует переподключения.

Предпочитайте один тип условия. Несколько типов — AND, обычные значения одного списка — альтернативы. Домены/IP дополняются из установленного Geodata.

## Генерация и импорт

[Контракт Custom]({{< relref "/docs/configuration/custom-routing" >}}) определяет поля, пустые слоты, действия, Local DNS и полные примеры. Обмен/импорт — через полный конфигурационный поток, не обычные Серверы.

Не включайте реальные узлы и direct/block outbounds. Неизвестные поля отклоняются. Помимо доменов, IP, портов и сети, дополнительные условия редактора поддерживают protocol/localOS. У каждого маршрута свой переключатель FakeDNS, по умолчанию выключенный. См. [совместимость]({{< relref "/docs/configuration/compatibility" >}}).

Local DNS независим от Tunnel DNS; только чистые прямые доменные правила формируют его domains. См. [DNS]({{< relref "/docs/configuration/dns" >}}). Собственные DAT требуют реальных файлов/категорий без конфликта имён.
