Собственный маршрут описывает обработку трафика, не привязываясь к конкретным серверам. Источник узлов выбирается на странице подключения.

## Создание

Добавьте маршрут в диалоге выбора трафика. Укажите уникальное имя и 1–3 входных узла для автоматического выбора или группы. Можно хранить до трёх маршрутов.

Правило содержит имя, действие (VPN, напрямую или блокировать) и до четырёх типов условий:

| Условие | Примеры |
| --- | --- |
| Сайты и домены | domain:example.com, geosite:cn |
| IP и подсети | 192.168.0.0/16, geoip:private |
| Порт | Порт или поддерживаемый диапазон |
| Сеть | TCP, UDP |

Предпочтительно заполнять один тип условия. Если типов несколько, **должен совпасть каждый**. Значения внутри одного типа — альтернативы. Домены и IP вводятся отдельными строками с подсказками из установленных данных.

Порядок правил важен. Удаление доступно в строке списка. Нет выключателя отдельного правила или панели дополнительных условий.

## Локальный DNS

Каждый маршрут сохраняет собственный адрес локального DNS, по умолчанию `8.8.8.8`. Его используют домены прямых правил; DNS через прокси остаётся `8.8.8.8`. Сопоставление доменов создаётся из прямых правил, а не из условий IP, порта или сети. Одного прямого правила по IP недостаточно для разрешения внутренних имён.

При обмене используется стандартное поле `dns.servers` с фиксированным `tag: app-dns-direct`; сохраняется только `address` этого сервера. Положение в массиве не имеет значения. Создаваемые при запуске списки доменов, резервные настройки и стратегия запросов не экспортируются. Старые маршруты без DNS используют прежний адрес по умолчанию; произвольную структуру DNS задавайте в Raw JSON.

## Сохранение и обмен

Кнопки внизу страницы сохраняют весь маршрут. Редактор правила меняет черновик; активный маршрут после сохранения требует переподключения.

Импорт и обмен используют тот же полный конфигурационный процесс, что Raw JSON. Минимальный пример с двумя пустыми входными слотами:

```json
{
  "name": "Local network direct",
  "outbounds": [{}, {}],
  "dns": {
    "servers": [{"tag": "app-dns-direct", "address": "8.8.8.8"}]
  },
  "routing": {
    "domainStrategy": "IPIfNonMatch",
    "rules": [
      {
        "ruleTag": "Private addresses",
        "ip": ["geoip:private"],
        "outboundTag": "direct"
      },
      {
        "ruleTag": "Example through VPN",
        "domain": ["domain:example.com"],
        "balancerTag": "proxy"
      }
    ]
  }
}
```

При хранении и экспорте outbounds содержит только пустые слоты. Не добавляйте определения direct или block: их создаёт OneXray при проверке и запуске. Ссылки на действия в правилах сохраняются.

Стратегия фиксирована: IPIfNonMatch. Имя правила — ruleTag, поле type отсутствует. Для неподдерживаемых полей или полных определений узлов используйте [Raw JSON]({{< relref "/docs/connect/raw-json" >}}).

## Зависимости

Экспорт может включать geodata.assets с именем файла и HTTPS URL. Стандартные geosite.dat и geoip.dat не включаются. При импорте зависимости скачиваются; совпадение имени с существующим файлом приводит к отказу, а не перезаписи.
